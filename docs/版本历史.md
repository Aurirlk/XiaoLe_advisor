# 版本历史

## v0.4.1 (2026-08-17) — 硅基 Embedding 接入 + 交接手册 + 环境坑修复

> 交接版本：项目进入维护期（原作者将更换设备后继续），新增完整交接手册，后来者读文档即可掌握全貌。

### Embedding 切换硅基流动 API（核心变更）
- **新增 `tools/siliconflow_embedder.py`**：SiliconFlowEmbedder（encode 接口兼容 SentenceTransformer，BGE-M3 1024 维，批量 16 + 缓存 4096）
- **`tools/embedding_config.py` 新增 `resolve_embedding_provider()` + `get_embedder()` 统一入口**：`vector_config.yaml` 的 `embedding_provider`（siliconflow/local）单一真源切换，所有向量模块（vector_store/xuefeng_store/multi_embedding_store）复用，杜绝双向量空间
- **`configs/vector_config.yaml`**：`embedding_provider: siliconflow` + `embedding_model: BAAI/bge-m3`（原 MiniLM 384 维）
- **兼容适配**：三处 `_embed` 统一处理 ndarray/list 两种返回（`.tolist()` / `np.asarray()`）；`multi_embedding_store` dense 向量转 ndarray 支持矩阵乘
- **动机**：本地 MiniLM 中文语义噪声大 + Windows pyarrow segfault 环境坑 → 改用硅基 API 消除本地依赖、中文更强
- ⚠️ **切换后需重灌索引**（384→1024 维）：`rebuild_embedding_index.py --force` + `check_xuefeng_milvus.py --enable --rebuild`（因开发机内存不足，最终端到端验证留待维护期执行）

### 脚本健壮性修复
- `scripts/rebuild_embedding_index.py` / `scripts/check_xuefeng_milvus.py` 补 `load_dotenv(.env)`（根因：独立脚本不加载 .env → SILICONFLOW_API_KEY 缺失 → 硅基 embedder 抛错降级 → 重灌失败）

### 文档
- **新增 `docs/交接手册.md`**：项目全貌、环境搭建、启动/数据恢复、已知坑全清单（chromadb Windows 三大坑、Docker 中文目录名、内存不足、pyarrow segfault、Docker Hub 慢等）、核心模块速查、面试叙事要点、遗留事项
- `docs/技术文档.md`：雪峰语料库 Embedding 描述更新 + 新增「4.6.1 Embedding 体系」章节
- `docs/项目简介.md`、`README.md`：同步 v0.4.1 变更

### 环境坑记录（详见交接手册第 6 节）
- **pyarrow 24→21 降级修复 segfault**（`import sentence_transformers` 即崩 EXIT=139）
- **chromadb 1.5.9 Windows 三大坑**：大批量 add compaction 崩溃 / delete_collection 后重建写入冲突 / close 后同进程复用崩

## v0.3.0 (2026-07-31) — 真流式输出 + Embedding 统一 + RAG 评估体系

> 架构升级版（企业级代码审查 P0/P1 修复之后），面向"可 review"的工程化改造。

### 真流式输出（原 P1-1）
- `/stream/advice` 与 `WS /ws/chat` 改用 `stream_mode=["updates","messages"]` 双流并行
- `synthesis_agent` 改 `llm.astream` 聚合（原 `ainvoke` 一次性生成，token 回调不触发）
- `dependencies.py` 的 LLM 构造开启 `streaming=True`
- 路由层只放行 `AIMessageChunk` 增量（过滤 supervisor 推理与最终完整 AIMessage，防重复拼接）；无流式时自动兜底整段

### Embedding 模型统一（原 P1-9）
- 模型名统一从 `vector_config.yaml` 单一真源解析（`tools/embedding_config.py`），`vector_store` 与 `multi_embedding_store` 共用同一模型
- 本地模型目录优先（离线可用）；切换模型用 `scripts/rebuild_embedding_index.py` 重灌

### RAG 评估体系（原 P1-12）
- `scripts/rag_eval/`：30 条领域标注集 + Recall@k/Precision@k/MRR/NDCG@k 评估脚本，可选 LLM faithfulness
- **指标基准**：Recall@3=0.567 / MRR=0.666（MiniLM 中文语义噪声大，`dense_weight` 由 1.0 标定至 0.3）

### 隐藏缺陷修复（FTS5 / Chroma / 中文分词）
- **FTS5 全文检索实为死路**：`rag_fts` 表建了但从未灌数据（0 行）+ unicode61 tokenizer 对中文近乎无效 → 改 trigram tokenizer + 启动幂等灌入 2287 条语料
- **Chroma 只同步 10/2287 条**：`collection_has_data()` "非空即跳过"导致永不同步补齐 → 改按条数比对，不足重灌
- **中文分词失效**：`re.split(r"\W+")` 把整句当单 token → 改 CJK 字符级 + 英文单词级混合分词
- **chromadb 1.5.9 + Windows 两坑**：① `persist_dir` 绝对路径打开 hnsw 段报错 → 统一转相对路径；② 非默认 Settings 触发 SharedSystemClient 冲突 → 用默认 settings；另 `hnsw:sync_threshold=100` 保证尾部语料落盘

### 意图离线沉淀（intent_tracker 接线）
- `log_intent`/`log_decision_journey` 此前零调用方 → 在 CRM 回调接线，synthesis 结果合并进 state 再回调；表 DDL 接入 `init_sqlite.py`

## V2.1 — SynthesisGuard 防端水引擎

V2.0 → V2.1 的核心升级：补上了 Agentic 系统中最危险的缺口——**确定性风控信号在 LLM 生成阶段的保真传递**。

系统具备了完整的"检测 → 指令注入 → 输出校验 → 强制修正"闭环：
- 即使 LLM 试图"端水"，输出层也会被强制纠正
- 即使 LLM 尝试把 `must_say` 改写或缩写，校验层会检测到缺失并重新注入
- 即使 LLM 把风险警告藏在回复末尾，位置校验会触发强制前置

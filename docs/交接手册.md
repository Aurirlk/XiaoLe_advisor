## 1. 项目是什么（30 秒版）

**小乐AI** 是一个"多 Agent 协同 + RAG 知识库"驱动的高考志愿填报决策系统：

- **多 Agent 协同**：Supervisor 路由中枢（场景/路径/决心度三层意图识别）→ 8+ 专业 Worker 员工（画像/匹配/就业/联网/写库）→ Synthesis 合成；Agent 间经通信总线（AgentCommunicationBus）协作、反思循环（ReflexionAgent）自纠、结果融合（ResultFusion）去冲突
- **RAG 知识库 + 图谱**：ChromaDB 向量检索 + SQLite FTS5 全文检索 + 知识域分权（kb_scope）+ Neo4j 知识图谱 + GraphRAG 多跳查询 + 张雪峰对话语料库（XuefengStore，Milvus/Chroma 双后端）
- **确定性风控**：SynthesisGuard 防端水引擎 + 红线审计 + 硬编码过滤
- **学习闭环**：write_Agent 唯一写权限 worker（联网搜索结果校验去重后自动入库，越用越懂）

**核心叙事（面试/简历用）**：多 Agent 协同（中枢-员工 Sisyphus 模式）+ RAG/Neo4j/GraphRAG 知识库 + Harness 学习协作机制。

## 3. 环境搭建（完整步骤）

### 3.1 前置要求

- **Python 3.10+**（开发机实际用 3.11.15 Conda 环境 `zxf`）
- **Conda**（推荐）或 venv
- **至少一个 LLM 的 API Key**（DeepSeek 默认）
- **可选**：Docker Desktop（仅 Milvus 向量库需要；Chroma 降级路径不需要）

### 3.2 创建环境 + 装依赖

```bash
conda create -n zxf python=3.11 -y
conda activate zxf
pip install -r requirements.txt
```

> ⚠️ **PyArrow 版本坑（Windows segfault）**：`requirements.txt` 中 `pyarrow>=21,<22`（**21.0.0 是修复版本**）。若装到 24.x，`import sentence_transformers` 会直接段错误崩溃（EXIT=139），崩溃链 `pandas → pyarrow 24 __init__ → Windows access violation`。**千万别升级 pyarrow**。详见第 6 节坑 1。

### 3.3 配置

```bash
copy .env.example .env
```

编辑 `.env` 填入：
```ini
DEEPSEEK_API_KEY=sk-xxxxxxxx                # LLM（必填）
SILICONFLOW_API_KEY=sk-xxxxxxxx             # 硅基流动 embedding（v0.4.1 起，向量库必填）
HF_ENDPOINT=https://hf-mirror.com           # 国内 HF 镜像（若需下载本地模型）
```

> ⚠️ **`.env` 不入库**（gitignore 已配），独立脚本（`scripts/*.py`）已内置 `load_dotenv`（v0.4.1 修复），直接运行即可读到 key。

### 3.4 初始化数据库 + 构建知识库

```bash
python scripts/migrate_questionnaire_fields.py
```

> 完整数据包（28 万条录取数据、原始爬取数据、模型）在百度网盘，见 README「数据下载」；不下载也能跑通对话，但位次/分数线查询返回空。

## 4. Embedding 体系（v0.4.1 核心变更，务必理解）

### 4.1 单一真源配置

`configs/vector_config.yaml` 是**全项目 embedding 唯一真源**：

```yaml
vector:
  persist_dir: data/chroma_db
  collection_name: zx_experience
  embedding_provider: siliconflow   # local（本地模型） | siliconflow（硅基 API，当前）
  embedding_model: BAAI/bge-m3      # 硅基模型 1024 维
  web_cache_collection: zx_web_cache
```

**统一入口**：`tools/embedding_config.py` 的 `get_embedder()`——所有向量模块（`vector_store` / `xuefeng_store` / `multi_embedding_store`）都从这里拿 embedder，**杜绝双向量空间不互通**（这是本项目历史修复的核心问题，见 4.3）。

### 4.2 切换 provider（local ↔ siliconflow）

| Provider | 说明 | 何时用 |
|---|---|---|
| `siliconflow` | 调硅基流动 API `BAAI/bge-m3`（1024 维），需要 `SILICONFLOW_API_KEY` | 推荐；无本地模型依赖、中文语义强、无 DLL 冲突 |
| `local` | 本地 SentenceTransformer（默认 MiniLM 384 维，或 BGE-M3），模型在 `data/models/` | 完全离线；但 Windows 有 segfault 风险（见坑 1） |

切换后**必须重灌索引**（维度可能变化）：

```bash
python scripts/rebuild_embedding_index.py --force   # 重建 zx_experience 集合
python scripts/check_xuefeng_milvus.py --enable --rebuild  # 重建雪峰语料库向量索引
```

### 4.3 为什么是"单一真源"（历史修复）

旧版系统有**双向量空间不互通**问题：
- `tools/vector_store.py` 默认 MiniLM（384 维）
- `tools/multi_embedding_store.py` 默认 BGE-M3（1024 维）

两处各用各的模型名 → Chroma 索引与多维检索无法共享向量。v0.3.0 统一到 `vector_config.yaml` 单一真源。**改模型名时务必重灌索引，否则查询维度不匹配直接报错。**

### 4.4 SiliconFlowEmbedder（`tools/siliconflow_embedder.py`）

- `encode(texts, normalize_embeddings=True)` 接口与 SentenceTransformer 完全兼容
- 内部：批量 16 条/请求 + 文本→向量缓存（上限 4096）
- 返回 `List[List[float]]`（非 ndarray）——**所有调用方已适配**（`_embed` 统一做 `tolist()` 或 `np.asarray()` 转换）

### 4.5 分类器模型（独立配置，勿混）

`vector.classifier_model`（默认 `paraphrase-multilingual-MiniLM-L12-v2`）是 **web_search_agent 平台分类**（query → 知乎/微博/贴吧/小红书/全网）专用本地模型：

- **独立于 RAG 向量空间**：模板向量与 query 向量同模型内部自洽，不参与 RAG 向量比较，故**不归入 embedding_model 单一真源**
- **刻意保持本地轻量**：每次搜索都要分类，走硅基 API 会引入延迟+成本
- 解析入口：`embedding_config.resolve_classifier_model()`；`web_search_agent._build_embedding_model()` 从配置读取，不硬编码
- ⚠️ 若本地无此模型，`SentenceTransformer` 会尝试从 HuggingFace 下载（国内先设 `HF_ENDPOINT=https://hf-mirror.com`）

| 数据 | 真相源 | 重建方式 |
|---|---|---|

## 6. 已知坑全清单（务必阅读）

> 以下坑全部在实际开发中踩过，按严重程度排序。

### 坑 1：`import sentence_transformers` 段错误（EXIT=139）— Windows

- **症状**：Python 进程直接崩溃，无 Python traceback，退出码 139（或 0xC0000005）
- **根因**：`torch` 加载后与 `pyarrow 24.x` 的 DLL 符号冲突（`pyarrow/__init__.py:71 create_module → Windows access violation`）
- **修复**：`pip install pyarrow==21.0.0`（已写死 requirements：`pyarrow>=21,<22`）
- **注意**：18.1.0 也不可用（`pa.json_` 不存在，datasets 4.8.5 要求 ≥21）；**21.0.0 是唯一正确版本**
- **验证**：`python -c "from sentence_transformers import SentenceTransformer"` 不崩即通过

### 坑 2：chromadb 1.5.9 Windows 三大坑（重灌/写入崩溃）

1. **同进程连续 add 大批量** → `Error in compaction: Failed to get hnsw segment writer`（小批量 16 条可过，batch=64 必崩）
2. **`delete_collection()` 后重建** → hnsw 物理段残留，写入冲突崩溃（新集合正常、删过的集合崩）
3. **`close()` 停 system 后同进程再开新实例** → `Could not connect to tenant default_tenant`；中途 close 复用 → `'RustBindingsAPI' object has no attribute 'bindings'`

**规避策略**：
- 写入/重灌用**小批次**（batch_size ≤ 16）
- 重灌先删整个 `data/chroma_db/` 目录（比 `delete_collection` 干净），再重建
- 一个进程内**不要**中途 `close()` 后继续操作；最后统一 close
- 遇到 `chroma_db_broken_*` 目录 = Chroma 崩溃自动重命名的坏索引，删除即可

### 坑 3：内存不足（os error 1455 / 页面文件太小）

- **症状**：模型加载时报 `os error 1455`，或 PowerShell/进程 fork 崩溃（`Resource temporarily unavailable`）
- **根因**：开发机内存有限（16GB），Docker Desktop（vmmemWSL 占用 3.8GB+）+ 浏览器 + 开发工具同时跑会吃满
- **规避**：
  - 跑 embedding 重灌 / Docker 前，先关掉浏览器和无关程序释放内存
  - Milvus standalone 需约 2GB 内存，Docker Desktop 本身再占 2-4GB
  - 重灌 2287 条索引约需 3-5 分钟 + 143 次硅基 API 调用，期间不要并行跑其他重活

### 坑 4：Docker 中文目录名 → project name 为空

- **症状**：`docker compose up` 报 `project name must not be empty`
- **修复**：始终 `docker compose -p xiaole up -d ...`（`-p` 指定项目名）

### 坑 5：Docker Hub 拉镜像极慢

- **症状**：`docker pull milvusdb/milvus:v2.4.4`（约 1.2GB+）在直连/部分加速源下卡几十分钟
- **实测**：`docker.m.daocloud.io`（DaoCloud）源最快；`docker.1panel.live` 对 milvus 镜像 403；`docker.chenby.cn` 不通
- **做法**：`docker pull docker.m.daocloud.io/milvusdb/milvus:v2.4.4` 后 `docker tag` 回标准名再 compose up
- 系统已配加速源（`~/.docker/daemon.json` 中 `docker.1panel.live` 等），但 milvus 大镜像仍建议 DaoCloud

### 坑 6：独立脚本不加载 .env

- **症状**：`scripts/*.py` 直接运行时读不到 `SILICONFLOW_API_KEY`（硅基 embedder 抛错 → 降级本地模型 → 本地没 BGE-M3 → HF 下载失败/超时）
- **修复**（v0.4.1 已做）：`rebuild_embedding_index.py` / `check_xuefeng_milvus.py` 开头加 `load_dotenv(ROOT / ".env")`
- **教训**：新增独立脚本时同样要加

### 坑 7：切换 embedding 模型后不重灌 → 维度不匹配

- **症状**：Chroma 查询报维度错误（384 vs 1024）
- **修复**：换模型/换 provider 后必须重灌（见 4.2），旧索引与新模型维度不兼容

### 坑 8：`data/` 大文件不入库

- 录取数据库（55MB）、本地模型（465MB）、爬取数据、向量库全部 gitignore
- 分发走百度网盘（见 README「数据下载」）；克隆后需手动下载解压
- 真相源 JSON（`data/vector_store/*.json`）同样被 gitignore——**但可以随时从 `data/documents/` 用 `build_rag_index.py` 重建**（README 有说明）

## 8. 面试 / 简历叙事要点

1. **主线**：多 Agent 协同（中枢-员工 Sisyphus 模式）+ RAG/Neo4j/GraphRAG 知识库 + Harness 学习协作机制的高考志愿决策系统
2. **Milvus 这条线是面试 JD 锚点**（「向量库 Milvus/FAISS/PGVector 部署与优化」）：雪峰语料库用 Milvus（HNSW/COSINE），不可达自动降级 Chroma——体现**按需选型 + 降级兜底**的工程思维
3. **数据分层治理**：确定性数据走 SQL、经验知识走 RAG、关系知识走图谱、对话风格走雪峰语料库——各层各司其职、互相兜底
4. **Embedding 选型**：本地 MiniLM（384 维）中文噪声大 + Windows DLL 冲突 → 切换硅基 BGE-M3（1024 维）API，体现**识别环境约束、选择更优方案**的判断力
5. **注意**：雪峰语料为模拟风格（非张雪峰真实语录），面试需说明或换真实素材

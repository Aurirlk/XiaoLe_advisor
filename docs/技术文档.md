### 1.2 数据流

```
用户输入 → Supervisor Agent → Worker Agent → 工具调用 → 数据层
    ↓

    ↓
```


## 4. 核心技术体系详解

### 4.1 服务工厂体系

**设计理念**：去硬件绑定、动态创建、运行时切换

| 工厂 | 支持 Provider | 特殊能力 |
|------|--------------|---------|
| LLMFactory | DeepSeek/Qwen/GLM/Doubao/Kimi/Ollama | 自动回退、成本追踪 |
| ASRFactory | FunASR/AliASR/BaiduASR/讯飞ASR | 本地/云端混合 |
| TTSFactory | EdgeTTS/CosyVoice/AliTTS/讯飞TTS | 情绪参数、流式合成 |
| VLLMFactory | GLM-4V/Qwen-VL/GPT-4o | 图片分析 |

**配置示例**：
```yaml
# configs/.config.yaml
selected_module:
  LLM: deepseek-v4-flash    # 改这一行即可切换模型
  ASR: FunASR
  TTS: EdgeTTS
  VLLM: glm-4v-flash
```

### 4.2 重试熔断体系

**三层防护**：
1. **重试层**：指数退避（1s → 2s → 4s → 8s），最多 3 次
2. **熔断层**：三态机（CLOSED → OPEN → HALF-OPEN），5 次失败触发
3. **回退层**：自动切换备用 Provider，保证服务可用

**全链路覆盖**：
- LLM 调用：失败自动重试 → 熔断 → 回退到备用模型
- ASR 识别：FunASR 本地失败 → 回退到云端 ASR
- TTS 合成：EdgeTTS 失败 → 回退到 CosyVoice
- SQL 查询：精确查询失败 → 模糊查询 → 关键词搜索

### 4.3 成本控制体系

**追踪维度**：
- Token 用量：输入/输出/总计
- 调用次数：按 Provider 分类
- 成本计算：内置 10+ 模型定价表
- 预算管控：日限额/月限额/硬上限

### 4.4 语音交互体系

**全链路流程**：
```
用户语音 → VAD 端点检测 → ASR 识别 → LLM 处理 → TTS 合成 → 语音输出
                  ↓
          意图打断（TTS 播放时支持语音打断）
```

**技术亮点**：
- **VAD 检测**：Silero VAD 实时端点检测（前端 RMS + 后端 ONNX）
- **意图打断**：AudioManager 单例管理，支持随时打断 TTS 播放
- **情绪 TTS**：根据情绪标签调整语速/风格（高兴→快/活泼，悲伤→慢/低沉）

### 4.5 防端水体系

**三层防线**：
1. **信号检测层**：识别 LLM 输出中的端水信号（"综合来看"、"各有利弊"等）
2. **Prompt 注入层**：在 system prompt 中注入硬约束（"必须给出明确建议"）
3. **输出校验层**：强制修正端水输出（SynthesisGuard 硬约束引擎）

**设计原则**：
- 确定性风控信号不能被 LLM 篡改
- 数值逻辑不进向量库
- 规则引擎不交给大模型
- 服务挂了不阻断启动

### 4.6 RAG 检索体系

**四级降级链**：
```
SQL 精确查询 → ChromaDB 向量检索 → FTS5 全文检索 → 关键词混合召回
```

**混合搜索**：
- ChromaDB 向量检索（语义相似度）
- FTS5 全文检索（关键词匹配）
- 关键词混合召回（扩展召回）
- RRF 融合排序（Reciprocal Rank Fusion）
- 交叉编码器重排序（精准排序）⚠️（`tools/reranker.py` 零调用方，标注留用）

**知识域分权（v0.4.0）**：
- `RAGTools` 新增 `kb_scope` 参数：`None`=全库 / `"majors"` / `["employment","majors"]` / source 前缀列表
- 三路检索统一按知识域限定（Chroma `where` + FTS5 `source LIKE` + 关键词过滤）
- `KB_SCOPES` 常量映射语料 source 前缀：majors / universities / employment / guides / policies / xuefeng / web
- 跨库兜底：scope 内无结果时 fallback 全库并打 `fallback_cross_kb: True` 标记；域内有结果不跨库（防污染）
- `career_agent` 已接入 `kb_scope=["user:employment/","user:majors/","user:policies/","user:guides/"]`

### 4.7 多智能体协作体系（蓝图 Phase 3）

**设计理念**：中枢-员工（Sisyphus）模式 —— Supervisor 指挥中枢调度专业 Worker 员工，员工采集信息交回中枢汇总；Agent 间通过通信总线协作、反思循环自纠、结果融合去冲突。

**四大组件**：

| 组件 | 文件 | 能力 |
|------|------|------|
| Agent 通信总线 | `core/agent_bus.py` | 消息订阅/发布、请求-响应、广播；asyncio 友好、异常隔离、超时降级 |
| 自我反思 | `core/reflexion_agent.py` | 输出质量评估（确定性规则，零 LLM 可离线）→ 改进建议 → 重试循环 → 反思记忆沉淀/复用（主题 LRU） |
| 结果融合 | `core/result_fusion.py` | 合并/投票/加权/专家四种融合策略；`build_graph(enable_result_fusion=True)` 时作为 synthesis 前节点 |
| 写库闭环 | `agents/workers/write_agent.py` | 唯一写权限 worker：写前校验（噪声过滤）/去重（source hash）→ RAG JSON `user:web/` 域 + Chroma 双写 |

**图结构（v0.4.0）**：
```
web_search_agent → write_agent → (result_fusion) → synthesis
supervisor → {profile, parent, family, match, career, sql, decision_detector} → synthesis
```

**Agent Bus 接入（蓝图 Phase 3.1 落地，2026-08-07）**：
- `build_graph(enable_agent_bus=True)` 实例化 `AgentCommunicationBus`（节点间旁路通道，不干扰 LangGraph 条件路由）
- **请求-响应**：graph_builder 注册 `match.admission` 订阅者（SQL 查"该分数能上的院校"）；`career_agent` 通过 `bus.request` 请求录取数据，并入 career_context（"可冲院校参考（Agent 总线协作）"）——跨 worker 协作不依赖 state 顺序
- **事件发布**：`match_agent` 完成后 `bus.publish("match.completed")`（供订阅方复用）
- **统计**：`bus_stats`（published/requests/replies）写入 state，供 review / 面试展示

**反思流程（蓝图 Phase 3.2 落地，2026-08-07）**：
```
Worker 输出 → ReflexionAgent 规则评估 → 质量达标？→ 通过（写 reflexion_report）
                          ↓ 不达标
                      改进建议 → regenerate 重试（上限控制）→ 反思记忆沉淀
```
- match/career 输出后写 `reflexion_report`（satisfied/issues/suggestions/reflections）到 state
- career 空结果/缺关键要素时，regenerate 放宽 kb_scope 全库重查并**追加**（不覆盖 bus 协作等已有数据）
- `dependencies.py` 生产默认开启 `enable_agent_bus=True, enable_reflexion=True`

**雪峰对话语料库（XuefengStore）**：
- 切块：轮次边界 `_split_turns`，超长按句切（MAX_TURN_CHARS=800）
- Embedding：复用统一学科模型（向量空间与主 RAG 一致，本地优先）
- 后端：Milvus（`MILVUS_ENABLED=1`，HNSW/COSINE）→ 不可达自动降级 Chroma `zx_xuefeng` collection
- 检索：专业关键字窗口词（2-3 字滑动窗口） + 向量混合，向量失败关键字兜底
- 接入：synthesis_agent 生成时 `to_thread` 检索雪峰原话注入 `payload.xuefeng_style_refs` 作为风格锚点（失败静默跳过）
- 语料：`scripts/build_xuefeng_corpus.py` 内置 3 条种子语料（医学/冲稳保/城市vs学校）；真实对话放 `data/xuefeng_dialogues/` 后跑脚本

**使用方式**（`core/graph_builder.py`）：
```python
graph = build_graph(
    enable_write_agent=True,     # 开启 web_search → write_agent 写库闭环
    enable_result_fusion=True,   # 开启多源结果融合节点
    xuefeng_store=store,         # 注入雪峰语料库（风格锚点）
)
```

## 6. 前端架构（Vite + Vue 3 SPA）

### 6.1 架构概览

V7.0 从 Flask UI + CDN Vue 2 迁移到 **Vite 5 + Vue 3 SPA**，由 FastAPI 在 8000 端口统一 serve 静态文件。

```
Vite 构建流程:
  frontend/src/*.vue + *.js + *.css
    → Vite 打包
    → frontend/dist/ (index.html + assets/*)
```

## 9. 部署指南

### 9.1 本地部署

```bash
# 1. 克隆项目
git clone <repo-url>
cd 小乐高考志愿填报助手

# 2. 创建环境
conda create -n zxf python=3.10 -y
conda activate zxf

# 3. 安装后端依赖
pip install -r requirements.txt

# 4. 配置
copy .env.example .env
# 编辑 .env 填写 API Key

# 5. 构建前端 SPA（重要！）
cd frontend
npm install
npm run build
cd ..

# 6. 初始化数据库
python scripts/init_sqlite.py
python scripts/build_rag_index.py

# 7. 启动服务
python -m api.main
```

启动后访问 **http://127.0.0.1:8000**（单端口统一 serve）。
